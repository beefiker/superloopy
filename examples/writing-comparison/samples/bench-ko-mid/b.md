# 설정 동기화 서비스 전환 검토

## 1. 현황
- **12개 서비스**가 각자 `config.yaml`을 복사해 사용 중입니다.
- 지난 분기 설정 불일치로 **장애 4건**이 발생했고, **평균 복구 시간은 38분**이었습니다.
- 동기화 워커는 저장소 연결이 끊기면 **이전 값을 그대로 사용하며 경보를 내지 않습니다.**
- 형식이 잘못된 값은 **무시됩니다.**

## 2. 전환 후 구조
- 모든 설정은 **`settings` 테이블**에 두고, 스키마는 **`schemas/settings.v2.json`**을 기준으로 합니다.
- **프록시**가 설정 변경 이벤트를 각 서비스에 전달하므로 **서비스 코드는 수정하지 않습니다.**
- 각 서비스는 **기동 시 한 번 읽고**, 이후에는 변경 이벤트를 받을 때만 다시 읽습니다.
- 설정 변경은 **관리 콘솔에서만** 수행하고, 이력은 **`settings_history` 테이블에 90일** 보관합니다.

## 3. 동작 원칙

| 항목 | 처리 방식 |
| --- | --- |
| 반복 적용 | 같은 설정을 여러 번 적용해도 결과가 동일함(**멱등**) |
| 일시적 연결 오류 | **재시도** |
| 스키마 검증 실패 | **이전 설정 유지** 후 **오류 로그** 기록 |
| 배포 | 워커는 **진행 중인 동기화를 마친 뒤 종료** |

## 4. 전환 일정

| 단계 | 대상 | 환경 | 일자 |
| --- | --- | --- | --- |
| 1단계 | 결제, 알림 서비스 | 스테이징 | 2026-10-15 |
| 2단계 | 나머지 10개 서비스 | 운영 | 2026-11-05 |

## 5. 확인 항목
1. **2단계 전에** 12개 서비스의 설정값을 `settings` 테이블과 대조합니다.
2. **1단계에서 불일치가 발견되면** `config.yaml` 복사 방식으로 롤백하고 원인을 기록합니다.
3. **운영 적용 첫날부터** 동기화 실패 건수와 경보 발생 여부를 모니터링합니다.

## 6. 미결 사항
- **서비스별 예외 설정 처리 방식**은 2단계 전에 논의해 결정합니다.
