# 팀 위키 도입 제안

**문제:** 운영 문서가 메신저, 개인 문서, 공유 폴더에 나뉘어 있습니다. 최신 절차를 찾기 어렵고, 새 담당자는 같은 질문을 반복해서 받습니다. 바뀐 기준이 어느 문서에 반영됐는지도 확인하기 어렵습니다.

**제안:** 운영팀 8명이 팀 위키를 3개월 시험 도입합니다. 전체 이전 대신 자주 쓰는 절차부터 정리합니다.

## 장점

1. [찾기] 온콜, 배포, 고객 문의 절차를 한곳에서 확인해 인수인계 시간을 줄입니다.
2. [기록] 변경 이력과 검토자를 남겨 오래된 안내의 재공유를 줄입니다.

## 고려할 점

1. [초기 작업] 문서 구조를 정하고 기존 자료를 옮길 시간이 필요합니다.
2. [중복] 사용 규칙이 없으면 메신저와 위키에 같은 내용이 남을 수 있습니다.

| 항목 | 월 비용 | 대상 |
| --- | ---: | --- |
| 위키 기본 요금 | 월 29,000원 | 운영팀 8명 |
| 초기 정리 시간 | 내부 배정 | 자주 쓰는 절차 |
| 시험 기간 | 3개월 | 사용 기록 검토 |

온콜 문서, 배포 체크리스트, 고객 문의 분류 기준만 먼저 옮깁니다. 매달 조회 수와 중복 문의 수를 확인합니다. 효과가 없거나 부담이 크면 계약을 연장하지 않고 기존 공유 폴더 방식으로 돌아갑니다. 새 문서에는 검토자를 지정하고 기존 자료에는 원본 위치를 남겨 중복 이동을 막습니다. 월별 검토에는 문서를 찾는 데 걸린 시간도 넣어 운영팀이 평가합니다.

**사용 규칙 확인:** 새 문서를 만들기 전 위키 절차를 먼저 확인합니다. 같은 내용이 메신저에 다시 올라오면 링크로 안내해 규칙이 실제로 지켜지는지도 봅니다.
