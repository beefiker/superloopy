# 팀 위키 도입 제안

현재 운영 문서가 메신저, 개인 문서, 공유 폴더에 나뉘어 있어 최신 절차를 찾는 데 시간이 걸립니다. 새 담당자가 들어오면 같은 질문을 여러 번 받고, 변경된 기준이 어느 문서에 반영됐는지 확인하기 어렵습니다. 이를 줄이기 위해 팀 위키를 3개월 동안 시험 도입하는 방안을 제안합니다. 대상은 운영팀 8명이며, 기존 문서를 모두 옮기기보다 자주 쓰는 절차부터 정리합니다.

## 장점

1. 온콜, 배포, 고객 문의 절차를 한곳에서 찾아 담당자 인수인계 시간을 줄일 수 있습니다.
2. 문서 변경 이력과 검토자를 남겨 오래된 안내가 다시 공유되는 일을 줄일 수 있습니다.

## 고려할 점

1. 초기에 문서 구조를 정하고 기존 자료를 옮기는 시간이 필요합니다.
2. 사용 규칙이 없으면 메신저와 위키에 같은 내용이 중복될 수 있습니다.

| 항목 | 월 비용 | 대상 |
| --- | ---: | --- |
| 위키 기본 요금 | 월 29,000원 | 운영팀 8명 |
| 초기 정리 시간 | 내부 배정 | 자주 쓰는 절차 |
| 시험 기간 | 3개월 | 사용 기록 검토 |

3개월 동안 온콜 문서, 배포 체크리스트, 고객 문의 분류 기준만 우선 옮깁니다. 매달 문서 조회 수와 중복 문의 수를 확인하고, 종료 시점에 유지 여부를 결정합니다. 효과가 없거나 관리 부담이 크면 계약을 연장하지 않고 기존 공유 폴더 방식으로 돌아갈 수 있습니다. 시험 중 새 문서는 반드시 검토자를 지정하고, 기존 자료는 원본 위치를 남겨 중복 이동을 막습니다. 월별 검토에는 문서를 찾는 데 걸린 시간도 포함해 운영팀이 직접 평가합니다.

시험 기간에는 새 문서를 만들 때 먼저 위키에 있는 절차를 확인합니다. 같은 내용이 메신저에 다시 올라오면 링크로 안내해 사용 규칙이 실제로 지켜지는지도 봅니다.
